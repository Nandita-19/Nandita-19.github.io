Independent technical project

AML Transaction Monitoring

A rules-driven pipeline for screening transaction behavior, with emphasis on structuring patterns and unusual transaction velocity.

PostgreSQLSQLApache AirflowData quality

Why this work matters

Transaction datasets often contain patterns that are difficult to spot through manual review. This independent project explores repeatable SQL checks that help surface transactions requiring further review; a rule hit is an investigative signal, not proof of wrongdoing.

My approach

  • Prepared a PostgreSQL-based environment to run repeatable transaction analysis.
  • Developed structuring checks and transaction velocity / volume logic with SQL.
  • Used an Airflow DAG to orchestrate monitoring checks, with emphasis on reproducibility and dependencies.
  • Organized the checks by detection category so additional rules can be added and tested independently.
